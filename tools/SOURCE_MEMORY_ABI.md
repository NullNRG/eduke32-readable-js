The current source compiler uses `source-lp64-addresses/2` for native JavaScript byte storage. Pointer fields and pointer/integer casts share the same 64-bit address representation. This replaces the older opaque pointer tokens; modules using the two representations must not be linked together.

`source_address_runtime.mjs` assigns aligned, disjoint address regions to original ArrayBuffers. C allocation uses the existing `runtime/abi.mjs` heap and its real byte offsets, stable views during growth, allocation records and free list. These are source-language memory adapters over native JavaScript buffers. They execute no machine instructions or intermediate-code interpreter. Original allocator functions remain readable generated functions.

`source_c_heap_runtime.mjs` provides the standard C malloc/calloc/realloc/free boundary, including 16-byte malloc alignment, allocation failure, preserved data during reallocation and invalid-free diagnostics. C allocations start at or above 65536: the original pool treats pointer values at or below 16384 as sentinels. Recycled browser-service blocks obey this same address floor. A configured program requires a matching complete semantic-index ownership contract with no original C allocator replacements. Clang must also prove the exact canonical C signature and C linkage; a similarly named C++ namespace function is rejected. Filtered recovery queries the same original translation unit for missing declaration metadata. Class-specific allocation, placement construction, and original game allocator functions retain their original ownership.

Browser startup should construct `NativeRuntime`, call `runtime.bindSourceMemory()`, then dynamically import compiled modules that can perform global initialization. This binds browser services and source C allocation to the same heap. The source adapter otherwise creates the same ABIHeap lazily for standalone compiler tests. Replacing an established heap is rejected.

Generation records `native_pointer_abi` on manifests and imports. The global linker and fragment importer reject mismatched providers. Recompile affected modules and dependent providers after this ABI change; the old 113-unit baseline and October 20 integration are historical inputs, not current-compatible executable artifacts.

Verified evidence includes source-level native comparisons for pointer bits in allocation headers, aligned addresses, aliases, realloc, calloc pointer slots, cross-module freeing, heap growth and invalid-address rejection. All eight original `sm::GenericAllocator` methods also pass native/Node/Chromium comparisons. This does not establish the original small-pool allocator, console initialization, engine startup or gameplay. Non-byte class object layout, placement construction, owned C++ subobjects and full browser service pointer bridging remain separate requirements.
